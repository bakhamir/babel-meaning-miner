Дата: 2026-11-05. Машина: Windows, Intel Core i5-10400F, 6 физических/12 логических процессоров. C++20, Zig/Clang 0.17.0 toolchain, CMake/Ninja Release, SQLite 3.54.1. Генератор `splitmix64-v1`, 3200 символов, 29-символьный алфавит. Сырые журналы этой сессии: `runs/v03-20261105-233918/` (локальные артефакты, исключены из git). Старые пользовательские базы не изменялись.

## Вопросы и гипотезы

Почему нет кандидатов? Ожидаем ли мы проходы при реальном бюджете? Какая стадия ограничивает скорость? Сохраняется ли источник при остановке, параллельном исполнении и синтетической оценке?

## Аудит и изменения

В v0.2 найдены дубли словаря, небезопасное использование итератора после роста trie, отсутствие промежуточных контрольных точек, зависание cancellation, неполное восстановление конфигурации, сортировка/экспорт с большой загрузкой в память и бенчмарк с удалением предыдущей базы. v0.3 исправляет dedup/trie, вводит ограниченное окно работ и одного писателя, атомарные транзакции блока вместе с контрольной точкой, сохранение конфигурации и отпечатков входов, обработку исключений рабочих потоков. Старые схемы читаются после добавочной миграции; старые неполные конфигурации не выдаются за воспроизводимый resume.

Предложения остаются непрерывными исходными цепочками. Проход требует настоящих точек и пробелов, последовательных смещений и границ предложений. Структура прохода сохраняется отдельно вместе с каждым составляющим предложением. Межстраничное объединение не применяется: у независимых локальных страниц нет лингвистически значимого порядка.

## A/B: натуральный поиск

Seed=4242, 10 000 страниц, 32 000 000 символов, 4 потока, текущий словарь. В обоих режимах: 15 581 словарное совпадение, 28 групп из двух и более соседних слов, 0 кандидатов из трёх слов, 0 принятых предложений, 0 проходов. В окончательном passage-запуске: 0.724911 с, 13 794.8 страницы/с, 0.578426 с внутри записи БД. Отдельные слова по умолчанию не сохраняются в sentence/passage-режиме; счётчики сохраняются. Никакого внедрения в этих запусках не было.

## C: контролируемая оценка

Три положительные и три отрицательные явно синтетические строки внедряются в десять воспроизводимых случайных окружений каждая. Получено TP=30, FN=0, FP=0, TN=30; precision=1, recall=1. Обнаружение засчитывается только при совпадении начала и конца внедрённого текста и принятой грамматике. Проверены пропуск разделителя, постороннее предложение и неверное согласование. Это малая ручная проверка чувствительности, не оценка качества на репрезентативном английском корпусе.

Старые отложенные грамматические примеры: TP=4, FN=0, FP=0, TN=5. Тестовый N-граммный корпус `positive_train.txt` и отдельный `positive_heldout.txt`: perplexity=16.6111, 25 предсказываемых токенов, 8 неизвестных. Это тест реализации; файлы авторские MIT-фикстуры, не натуральный корпус. Большой корпус или модель не скачивались. Обучение принимает пользовательский корпус с законными правами использования, сохраняет воспроизводимый FNV-1a отпечаток (не криптографическую подпись). Kneser–Ney не добавлен: нет репрезентативного held-out корпуса, на котором можно обосновать усложнение.

## D: осуществимость

На 10 000 страниц ожидается лишь 0.0398 словарной тройки с одиночными пробелами. Вероятность нулевого результата приблизительно 96.1%. Для перечисленного конечного набора трёхсловных предложений среднее ожидание порядка 5.75e10 страниц. Два таких последовательных предложения имеют верхнюю границу интенсивности 3.37e-26 на страницу. Смысловая связность не имеет честно оценённой вероятности. Формулы, область применимости и границы доверия — в `FEASIBILITY.md`.

## Надёжность и ограничения

CTest включает отдельные наборы passage/grammar, model/feasibility, recovery/concurrency, миграционный smoke v1 и Python CLI/semantic. CLI-тест реально убивает дочерний процесс после durable checkpoint и проверяет возобновление без повторного счёта страниц. Экспорт проверяется JSON-парсером и SQLite integrity_check. Часть Python-тестов подключается при наличии Windows `py` launcher; вручную работает Python 3.12.

Связность — поверхностная эвристика, компоненты повторов/темы коррелируют; это не полноценная модель тем или разрешение местоименных ссылок. `COHERENT_PASSAGE` означает прохождение описанной эвристики, не доказанную семантику. Семантический адаптер Ollama работает отдельной командой по ограниченному экспорту, сохраняет отдельный результат с digest модели, не меняет текст/классификацию источника. Проверен mock HTTP-контракт/кэш/ошибки; живой установленной модели не проверяли.

Remote-бэкенд остаётся отключён: свежая попытка чтения сайта через поисковый инструмент завершилась timeout, API-репозиторий по-прежнему не содержит реализации; исторический формат не является доказательством текущей совместимости. Не выполнялись запросы к запрещённым robots маршрутам. Details: `REMOTE_INTEGRATION.md`.

## Воспроизведение

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\build\bmm.exe scan --mode passages --pages 10000 --threads 4 --seed 4242 --db runs/new-passages.db --json
.\build\bmm.exe evaluate --mode injection
.\build\bmm.exe feasibility --pages 10000 --min-sentences 2
.\build\bmm.exe benchmark --mode sentences --pages 10000 --store-words
.\build\bmm.exe score-passage --text "the cat sleeps. the cat wakes."
.\build\bmm.exe scan --source-mode constrained --mode passages --pages 20 --db runs/new-controlled.db --json
.\build\bmm.exe export --type passages --experiment 1 --db runs/new-controlled.db --format json --output runs/controlled-passages.json
```
