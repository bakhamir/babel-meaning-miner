# Оригинальная Library of Babel: статус интеграции

В BMM v0.3 удалённый бэкенд **отключён**. Не получена проверенная пара «точный адрес — полная страница» через устойчивый поддерживаемый интерфейс. Локальные адреса SplitMix64 не совпадают с адресным пространством официального сайта.

## Историческая проверка v0.2 — 2026-11-05

Во время v0.2 были зафиксированы следующие результаты:

- [`browse.cgi`](https://libraryofbabel.info/browse.cgi) открывался и описывал имя hexagon до 3260 строчных букв/цифр, 4 стены, 5 полок на стену и 32 тома на полку.
- [`robots.txt`](https://libraryofbabel.info/robots.txt) вернул HTTP 200 с запретами `/hexagon.cgi`, `/shelf.cgi`, `/wall.cgi` для `User-agent: *`. Это историческое наблюдение, а не утверждение, что правила с тех пор не менялись.
- Один POST к `download.cgi` с параметрами исторического клиента и тайм-аутом 20 секунд не получил ответ до истечения времени. Повторные загрузки и сканирование сайта не выполнялись.

Отсутствие запрета конкретного маршрута в robots.txt само по себе не подтверждает ни работоспособность API, ни условия использования автоматического доступа. Тайм-аут одного запроса также не доказывает, что маршрут окончательно закрыт.

## Повторное исследование v0.3

Согласно журналу исследования v0.3, свежая попытка чтения официального сайта через поисковый инструмент завершилась тайм-аутом. Это отдельная проверка доступности сайта, **не новый POST к `download.cgi`**. Запросы к указанным выше запрещённым CGI-маршрутам не выполнялись. Свежий успешно полученный текст страницы оригинальной библиотеки и проверка его повторяемости отсутствуют.

Проверенные материалы по-прежнему не дают готовой подтверждённой текстовой интеграции:

| Источник | Что установлено | Ограничение |
|---|---|---|
| [Официальный сайт](https://libraryofbabel.info/) | Источник оригинальных текстовых страниц | Текущая полная страница через программный интерфейс в v0.3 не получена |
| [librarianofbabel/LoB-API](https://github.com/librarianofbabel/LoB-API) | В просмотренном репозитории есть лицензия CC0 | Реализация/контракт рабочего API не найдены |
| [libraryofbabel.info-algo](https://github.com/librarianofbabel/libraryofbabel.info-algo) | README описывает алгоритм отдельной библиотеки изображений Babelia; заявлено CC BY-SA-NC | Не подтверждает отображение адресов текстового сайта; код не включён в BMM |
| [Исторический Python-клиент](https://github.com/victor-cortez/Library-of-Babel-Python-API/blob/master/pybel.py) | POST `hex`, `wall`, `shelf`, `volume`, `page`, `title` к `download.cgi`, затем обработка ответа; MIT | Исторический скрейпер не гарантирует актуальную схему ответа или доступность |

Похожие независимые генераторы с обратимым отображением также не считаются оригинал-совместимыми без эталонных страниц с совпадающими адресами и текстом. Исходное исследование лицензий и реализаций находится в `RESEARCH.md`.

## Поведение приложения

```powershell
.\build\bmm.exe remote-test --enable-network
.\build\bmm.exe verify --backend original
```

Обе команды сообщают об отсутствии проверенной интеграции и завершаются ненулевым кодом. Текущий `remote-test` выводит сохранённый статус блокировки; он не выполняет новую сетевую диагностику при каждом запуске. Флаг `--enable-network` сам по себе не включает недоступный адаптер. Попытка `scan --backend original-remote` отвергается; локальный генератор не используется как замена удалённому источнику.

Для включения отдельного адаптера нужны успешная одиночная загрузка разрешённым способом, точные параметры адреса, подтверждённые алфавит/длина страницы, повторное получение того же содержимого и выясненные условия доступа. После этого требуются ограничение частоты, тайм-ауты, проверка ответа, кэш и сохранение исходных координат. Эти требования не выдаются за уже реализованный remote-бэкенд. Локальные эксперименты от него не зависят.
